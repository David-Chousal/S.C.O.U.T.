## Changed 2026-10-28 — the shore station pushes to the console by itself (SCO-237)

- **Written, not yet run on the board.** A FreeRTOS task on core 0 (`firmware/src/shore_rx/shore_net.cpp`) joins WiFi, queues each new reading (256 readings, oldest dropped when full), pushes batches of 20 to `POST /api/device/readings` over HTTPS with the station's device token, retries with a 5 s to 10 min backoff, and reads requested transmit counts every 10 min. No computer is needed.
- **Rows match the Python to the character** (`lib/scout_console`): numbers are formatted with exact rounding, checked against vectors generated from `schema.py` (every battery millivolt 2.0–4.4 V, every turbidity count); a deliberate break in the tie rule was caught.
- **Clock (David's call):** NTP when online; otherwise the S3's internal clock, which keeps time between syncs and across resets (power-on excepted); `T<epoch>` over USB as before. Readings carry the buoy's timestamp, so the shore clock never touches data. A battery-backed clock is an open question for ECE.
- **Fallbacks stay (David's call):** the S3 still prints every frame over USB for the computer bridge (SCO-257), and the SD card is merged after retrieval.
- Credentials in the gitignored `src/shore_rx/shore_secrets.h`; without it WiFi stays off. HTTPS trusts eight roots, checked against the live console. A link-check build lets CI link the network code. 120 native tests and all seven firmware builds pass.
