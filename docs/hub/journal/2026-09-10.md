## Where the project stands

Software is in good shape and hardware has not arrived. Every subsystem that can be verified
without a board is verified; nothing has met a real sensor, radio, or water.

## Changed today

- **Repo-wide consistency audit.** The settled 30-byte packet size was propagated to eleven
  places still claiming 82 bytes — including the public website's spec table and CLAUDE.md's own
  Standing Rule 2. 59 broken links repaired (all depth errors, no missing files) and 17 dead
  anchors fixed. `facts.md` was correct throughout and was not touched.
- **Integration runbook written** ([Integration Runbook](../../engineering/integration-runbook.md)) —
  the full bench-to-field procedure: toolchain, what programs what, and ten staged bring-up steps
  each with a PASS gate. Written to be executed by a Claude session with a human doing only the
  physical work. Stage 0 is verified and runnable today; Stages 1–10 are specified but unrun,
  because no hardware exists.

## Raised today

- **🔴 New blocker: the Rev A pin map contradicts the firmware.** The schematic annotates
  `TEMP_DATA = Feather D5`; `config.h` has `PIN_ONEWIRE 12` and needs `D5` for the RTC wake
  interrupt. Flashed as-is, the DS18B20 never reads *and* the buoy cannot wake from standby.
  The Adalogger's PCF8523 `INT1` also needs a solder jumper that no assembly step calls for.

  This is the same class as the `PIN_TURBIDITY` A0→A1 error caught in
  [SCO-85](https://linear.app/scout1/issue/SCO-85) — that one was found, this one was not.
  Recorded as an open fact and a pending decision; **Isabella (ECE) owns the call**. Both
  resolutions are written up; the runbook holds a blocking gate until one is applied.
