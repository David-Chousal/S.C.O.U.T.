## Where the project stands

Session: writing the [Integration Runbook](../../engineering/integration-runbook.md) surfaced a
set of software gaps that the hardware blockers had been hiding. Three of them closed today, on
top of the RTC and radio work earlier in the day.

### The shore station became a real deployment target (CSEN)

Three separate problems, one underlying cause: nobody had walked the path from *a packet
arriving* to *a number on the public dashboard*. Each piece existed; none of them connected.

- **There was no publish path at all.** `shore/data/` is gitignored, so received CSVs could
  never have been committed. And the Pages workflow regenerated 30 days of simulated telemetry
  on an hourly cron and rebuilt the site from it unconditionally — so even a force-added real
  file would have been overwritten within the hour and relabelled *"not a live deployment"*.
  No error, no failed check, no diff. The dashboard would have kept looking healthy while
  showing nothing real. Received data now lands in a tracked `shore/data-live/`, the simulator
  writes only to the gitignored scratch directory, and the choice between them is made in
  tested code rather than in workflow YAML.
- **There was no service.** The receiver was a script someone ran by hand; a reboot or power
  cut ended reception silently, and because the buoy transmits blind neither end would have
  raised an alarm. It now runs under systemd with `Restart=always`, a clean SIGTERM stop, and a
  capped widening backoff so a dead radio does not pin the Pi's CPU.
- **The loop cannot use `link.pending`.** A real SX1276 cannot report a queue depth —
  `Rfm9xLink.pending` returns 0 and says so. A loop built on it passes every test against the
  mock and then sits idle forever against real sky. The service watches `stats.received`
  instead, and there is a test that pins exactly that.

### A contradiction that had been sitting in the canonical facts (cross-discipline)

[`facts.md`](../facts.md) asserted that the internal SoH temp/humidity sensor **"is fitted"**.
[Data Schema](../../engineering/data-schema.md) said those columns were **"not in the v1 BOM"**
and listed the sensor as an open question. The firmware had no code for it. All three had been
true-sounding and mutually incompatible for weeks.

The underlying decision was never in doubt —
[ADR-0005](../../decisions/0005-v1-sensing-payload.md) settled that a sensor *is added*, and its
value is real: humidity near zero in a sealed bay means a rise is a leak, the earliest warning
for the failure mode that ends a deployment. What never happened is everything after the
decision: no part number, no BOM line, no driver, no `schema_version` bump.

Nothing was reconciled by picking a side. `facts.md` now says **decided, not yet fitted**, the
schema points at the ADR instead of reading as undecided, and the actual open item — which part,
and does it make Rev A — is filed with an owner in
[`open-questions.md`](../research/open-questions.md). The
[decision log](../decision-log.md) row from 2026-08-17 was left exactly as written: it records
what was decided that day, which is still accurate.

### Two gaps closed that turned out smaller than first reported (CSEN)

Both had been described more alarmingly than the evidence supported, and checking narrowed them.

- **The acoustic stack on ARM** was called "an untested assumption". Querying PyPI turned it
  into a settled provisioning rule: **aarch64 is clean** — every pinned package and compiled
  transitive dependency ships an ARM wheel — while **armv7l has no wheel for nine of them**, so
  pip would build SciPy from source on a board that usually runs out of RAM trying. So the fix
  is one line in the provisioning docs (use the 64-bit image), not a porting effort. The check
  is a script, so it can be re-run when the pins change rather than re-argued.
- **"No backfill path off the SD card"** overstated it. `load_dir` already reads any directory
  of CSVs, so a card could always be analysed. What was missing was *merging* it with the shore
  record — and since the card is the richer copy (a 30-byte packet cannot carry `turbidity_v`,
  `turbidity_ntu`, or the audio filename), the merge also fills columns shore never had.
  Against a simulated 9-hour outage: **62.5% → 100% completeness, 1 gap → 0, and 0 → 48 rows
  with `turbidity_v`.**

## What's blocking

Unchanged from [`status.md`](../status.md). Nothing closed today was blocked on hardware, which
was the point of picking these three — the parts blocker ([SCO-88](https://linear.app/scout1/issue/SCO-88))
