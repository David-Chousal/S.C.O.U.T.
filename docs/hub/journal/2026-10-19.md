**Phase:** 2 — System Integration (2026-10-19 – 2026-11-25)

## Changed 2026-10-19

- **Integration runbook rewritten** before the first hardware test. The 2026-09-10 version still
  described a LiPo + solar power path, the 5 V SEN0189 behind a divider, HIGH = on sensor gates,
  wake on the PCF8523 interrupt, one packet a day, and a Raspberry Pi shore station. It now
  follows the build plan's Stages 1–9 and lists seven gaps found while checking it against the
  code:
  - **G1:** nothing sets the RTC, so timestamps and the UTC transmit slots are wrong on a new board.
  - **G2:** the path from the ESP32-S3 to the Python shore software is undecided.
  - **G3:** the Rev A KiCad schematic still puts the DS18B20 on D5.
  - **G4:** the firmware's SD file names don't match the schema, and the card importer finds none
    of them (tested).
  - **G5:** no receiver sketch exists for the bench link test.
  - **G6:** there is no way to force a watchdog reset for testing.
  - **G7:** audio capture isn't implemented.

  Stage 0 re-verified: 86 + 64 + 20 tests, packet contract OK, Flash 25.4%. See
  [Integration Runbook](../../engineering/integration-runbook.md).
- **`shore-station.md` flagged out of date** (still Pi-based).
- **Shore station doc rewritten to the agreed design.** The ESP32-S3 + LoRa FeatherWing *is* the
  shore station: FreeRTOS, WiFi push to the dashboard, wall-powered, downlink under ADR-0008. My
  earlier suggestion (forward frames to a host computer) was not what the team agreed and is
  dropped. The one open point is which dashboard back end receives the push (SCO-120). See
  [Shore Station](../../engineering/shore-station.md).
- **Bench readiness in code** ([PR #186](https://github.com/David-Chousal/S.C.O.U.T./pull/186)):
  clock set over USB (SCO-201), bench receiver and transmit-every-minute build (SCO-155), SD
  layout `/DATA/YYYYMMDD.CSV` with a case-insensitive importer (SCO-202). Runbook gaps G1, G4,
  G5 marked fixed in code. Correction: RadioHead's `spiWrite` is public; the erratum note said
  a subclass was needed.
- **System block diagram drawn** (Isabella): SCOUT-S-000 Rev A, one master sheet (36 × 24 in)
  with mechanical, electrical, firmware and data together, plus three 22 × 17 in zoom sheets,
  current through PR #187. See [System Block Diagram](../../engineering/system-block-diagram.md).
  Drawing it surfaced three inconsistencies, now in
  [open questions](../research/open-questions.md): a stale SF7 sentence in `facts.md`, the power
  budget counting 3 sends a day against the firmware's 9, and the housing flange bolt count
  (6 vs 8).
- **Mouser order was never placed** (Isabella, confirmed 2026-10-19). The runbook's "all parts
  for Stages 1–5 arrived 2026-10-16" and SCO-115 being Done are wrong for the Mouser half: the
  Grove turbidity sensor, DMG2305UX switches, CR1220 and adapters are still to order, and the
  order is being placed now. `purchase-log.md` ("not yet placed") was right. Stage 1 can start
  with the DS18B20; turbidity and Stage 3 wait on this order.
