## Changed 2026-10-30 — console audit fixes (David)

- **A power-cycled buoy's readings were being thrown away.** A cold start restarts
  `record_seq` at 0, and every dedupe layer keyed on `(buoy_id, record_seq)`, so the new
  readings looked like repeats. All four layers (S3 firmware, Python store, SD import, console)
  now key on `(buoy_id, record_seq, timestamp_utc)`. The console needs D1 migration 0002 applied
  to the live database before the next deploy.
- **The console now reads `RTC_LOST`:** a buoy whose clock lost power shows "buoy clock lost ·
  last heard …" and is judged fresh by when its rows arrive, instead of reading **Silent**.
- **The 404 page now lists Settings.**
- Linear refused a new issue for this work: the workspace is at the free plan's issue limit.

## Changed 2026-10-30 — one command station per buoy (David)

- **An admin picks which shore station sends each buoy's downlink commands** (Stations page), and
  only that station is told the requested count. A lone station needs no pick; with two and none
  picked, nobody sends, and the page says so beside any buoy with a request waiting. Revoking a
  station clears its picks. Migration 0004. Known gap: the USB bridge (`sync_console.py`) never
  clears a count it set earlier on the S3.
