## Changed 2026-10-30 — code audit and test sweep (David's request)

- **Everything run, everything green:** 135 shore, 289 telemetry and 29 acoustic-reference Python
  tests; the packet, bit-map, payload-ceiling and downlink contract checks; 50 console Worker tests
  and 49 front-end tests, lint and build; 124 firmware native tests; all seven firmware builds; and
  the acoustic pipeline end to end on the committed recordings (5 files, exit 0).
- **Fixed:** the buoy never flagged `RTC_LOST` on a clock that had lost power or was never set; a
  `startup_flags` variable meant to do it was computed and discarded. Every sample now checks
  `scout_clock_trusted()` (RTC answers, has not lost power, date on or after 2026-01-01), with 4
  native tests. Analytics already caught those rows by date, so no stored data was misread.
- **Fixed:** in the S3 shore firmware, `Serial.println` writes text and line ending separately, so
  a network-task line could split a frame line and the computer bridge would drop it. Every line
  is now one write, and `shore/tests/test_shore_firmware_lines.py` keeps `println` out.
- **New tests:** the S3's generated rows are now checked against the console itself, not just the
  Python (`console/test/shore-contract-test.js`: rows accepted and stored once, the 400 that names
  a bad row, the settings reply's keys, the 200-row limit); `check_packet_contract.py` now also
  checks `SCOUT_LINK_AIRTIME_MS` (691 ms) against the airtime model, and was shown to fail on the
  old 560 ms value.
- **Checked and fine:** float `printf` on the SAMD21 (the Adafruit core links the real
  `_printf_float`, so SD rows keep their decimals); the audio clip pets the watchdog; the downlink
  compares MACs in constant time and checks replay before freshness.
- **Filed:** [SCO-275](https://linear.app/scout1/issue/SCO-275), downlink replay protection when
  the buoy's RTC has failed (low; the downlink is off in every shipped build).
- **iCloud copies:** the repo sits on an iCloud-synced Desktop, which keeps creating `name 2`,
  `name 3` copies (1,500+ this week, including inside `node_modules`). They broke a local build,
  failed the conventions check and were once committed. `.gitignore` now ignores them.

## Changed 2026-10-30 — watchdog test build (David)

- **Runbook gate G6 closed in code:** a new env, `feather_m0_wdt_test` (the bench build plus
  `-DSCOUT_WDT_TEST`), logs one reading, then stops petting the watchdog on its second cycle.
  The watchdog fires about 16 s later and the next boot reports `watchdog_reset=yes`, with
  `WATCHDOG_RESET` in the SD row's `soh`. A boot the watchdog caused never hangs, so each
  power-on gives exactly one forced reset. The rule is in `lib/scout_wdt_test` with 4 native
  tests, and CI now builds the env. Not yet run on hardware; it is the watchdog line of
  Stage 5 ([SCO-160](https://linear.app/scout1/issue/SCO-160)).
- [SCO-98](https://linear.app/scout1/issue/SCO-98) moved to In Test: the modem config is in
  code; only the Stage 4a bench check is left.
