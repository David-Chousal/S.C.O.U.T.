**Phase:** 1 — Subsystem Bring-Up (2026-09-07 – 2026-10-23)

## Changed 2026-10-23

- **Analytics flag naming made consistent.** `run_pipeline.py` now takes `--audio-dir`, matching
  the hyphenated flags of the other analytics scripts; `--audio_dir` still works as an alias.
  The pipeline produces identical output with either spelling (checked end to end on the
  2017-08-01 Sesoko recordings). CLAUDE.md, both READMEs and the integration runbook updated
  ([SCO-26](https://linear.app/scout1/issue/SCO-26)).
- **Turbidity: FAU, not NTU, and the SEN0189 → Grove sweep** ([SCO-12](https://linear.app/scout1/issue/SCO-12)).
  The Grove 101020752 is a transmitted-light sensor, so a formazin calibration gives FAU (ISO
  7027-1); the column is now `turbidity_fau` everywhere (firmware header, shore schema, analytics,
  docs), with old CSVs still readable. Current-state docs, code comments and the public site now
  name the Grove sensor; historical records were left as written; the SEN0189-derived sensor-pod
  dimensions are flagged for re-check. **The Grove sensor has not been ordered**
  ([SCO-189](https://linear.app/scout1/issue/SCO-189)), which now blocks calibration, the bench
  turbidity checks, the final pod and the MVP turbidity reading.
- **Packet ceiling: 140 B** ([SCO-97](https://linear.app/scout1/issue/SCO-97)). Derived from the
  firmware's 2 s send timeout, not the EDD's 82 B or the radio's 251 B frame (which would time out
  at ~3.0 s). Firmware `SCOUT_LINK_PAYLOAD_CEILING_BYTES` and shore `LORA_PAYLOAD_BUDGET_BYTES`
  now share it; `check_packet_contract.py` recomputes the airtime from `config.h` in CI. Its first
  run caught my own rounding error in the airtime constant (1,740 → 1,739 ms).
- **One copy per slot** ([SCO-21](https://linear.app/scout1/issue/SCO-21)). The firmware had been
  sending 3 slots × 3 blind copies = 9 frames a day, an unexamined combination of the August
  repeat-3-times rule and the October 3-slot cadence. David chose 1 copy per slot: 3 sends a day,
  matching what the team and Isabella's power budget assumed. Found while preparing SCO-223.
  Also found: with every buoy on the same slot table, two buoys would transmit at the same moment
  and collide; a per-buoy offset is filed separately.
- **Over-the-air update design drafted** ([SCO-197](https://linear.app/scout1/issue/SCO-197),
  [design](../../engineering/ota-firmware-update-design.md)). Proposed: a 1 s listen window after
  each send (≈ 0.019 mAh/day, 0.14% of the budget), 128-byte chunks so every frame stays under
  the 140 B ceiling, Ed25519-signed images with the key kept offline, and a rebuilt SD-update
  boot stub that restores the last good image after 3 failed boots. Found while reading the
  Arduino stub: its default SD chip-select is pin 4, which is the RFM95 reset line on this
  Feather, so it cannot be used unmodified. Also: the buoy now needs the SX1276 500 kHz errata
  registers that only the shore applied until now. Window length waits on Isabella; the shore
  FeatherWing's FCC authorization is still unchecked.
